# Painted backgrounds

Every scene in the game is drawn by code, so the game always works with no image files.
You can replace any scene with a painted background generated by an AI image model.
The game picks up whatever painted backgrounds exist and keeps the code-drawn scene for
the rest, so you can do one room at a time.

## How it works

1. **Layouts**: `npm run art:layouts` renders each room's code-drawn scene to
   `art/layouts/<room>.png`. These are the composition references: they show the model where
   the horizon, doors, paths and open walkable ground are.
2. **Generate**: `npm run art:generate` sends each layout plus a prompt to a Gemini image
   model and saves the result to `art/raw/<room>.png`. The shared style prompt and the
   per-room descriptions live in `scripts/art-prompts.ts`.
3. **Process**: `npm run art:process` resizes each painting to the game's 320x200 pixel grid,
   reduces it to its own 256-colour palette with light dithering (like a real VGA screen) and
   writes `src/art/bg/<room>.png`. The game bundles these automatically.

Or run all three: `npm run art:all`.

## Setup

You need a Gemini API key with access to an image-generation model.

```bash
echo "GEMINI_API_KEY=your-key-here" > .env
npm install
npm run art:all
npm run dev
```

`.env` is git-ignored. The default model is `gemini-2.5-flash-image`; set
`GEMINI_IMAGE_MODEL` to use another. Image generation is billed per image by Google, so
check their current pricing first. A full run makes one request per room (24).

## Redoing a scene

Generated art varies from run to run. To try a room again:

```bash
npm run art:generate -- inn --force
npm run art:process -- inn
```

To go back to the code-drawn version, delete `src/art/bg/<room>.png`.

## What to check

- **Layout drift.** Models sometimes move things. The hero walks on the code's floor plan,
  not the picture, so if a doorway or path lands in a different spot, regenerate that room
  or edit the prompt in `scripts/art-prompts.ts`.
- **Objects you walk behind** (the well, trees, crates, counters) are cut out of the
  painting using the code-drawn shape as a mask. If the painted object is in a slightly
  different place, you'll see a sliver of the wrong pixels when the hero walks behind it.
- **Night and dusk** are applied by the game on top of the painting, along with lit windows,
  fires and other lights, so always generate daytime scenes.
- **Characters** are still drawn by the game in every scene. Painted characters in a
  background would be static, so the prompt asks the model not to include any.

## Options for processing

```bash
npm run art:process -- --colors=64     # a harsher, more limited palette
npm run art:process -- --no-dither     # smooth colour steps instead of dithering
```
